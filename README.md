# Baccarat

Punto banco against a shoe that lives in GitHub Actions, played by whoever turns up. Nothing to install, and no account beyond the one you already have: every bet is an issue, and the table is this file.

## How to play

Pick a spot (Player, Banker, Tie, or either pair) and click a chip in its row. The click opens an issue with the bet already written in the title. Press Submit, and about 30 seconds later the coup has been dealt by the standard tableau, the table above has moved, and the issue is closed with the result and a note on what that bet was worth.

Nothing is decided once the chip is down, so one click is one whole hand. There is one table and one hand at a time: a link drawn for an earlier hand is refused rather than played against a shoe the clicker never saw.

- Eight decks, dealt down to a cut card 16 cards from the end before the shoe is shuffled
- Every card that has come out of the shoe is listed under the table, and the bead plate shows every result of the shoe so far
- Each bet is priced exactly from the cards actually left in the shoe. The issue comes back with the value of all five spots, and what choosing a worse one gave up is added up per player
- Late in a shoe a tie or a pair bet sometimes has the edge over the house. The comment says so when it happened
- Every hand of the last 40 shoes, with each shoe's cards and road, is kept in [.github/baccarat-log.txt](.github/baccarat-log.txt)

## How it works

`scripts/baccarat.py` is the game: the state in [.github/baccarat.json](.github/baccarat.json), the settlement, and the renderer that writes the table between the two markers above. `scripts/bacmath.py` is the drawing rules and the exact odds of every bet, summed over every way the next four to six cards can come out. On a full eight-deck shoe it reproduces the published house edges: 1.06% on Banker, 1.24% on Player, 14.36% on Tie at 8 to 1. `.github/workflows/baccarat.yml` runs the game whenever an issue is opened whose title starts with `bac|`, then commits the redrawn README and closes the issue.

The cards in `.github/cards` are drawn by `scripts/make_cards.py` and committed rather than generated on each hand, so `.github/workflows/checks.yml` regenerates them on every pull request and fails if the committed art no longer matches its generator. It does the same for the table, redrawing it from the state file.
